# Cosmos DB NoSQL 0.26.0

Independent native query tabs and Windows x64 packages, building on 0.24.0.

Requires **DBX 0.6.59+**; use **DBX 0.6.68+ for native New Query tabs**. Package targets: **macOS ARM64 (Apple Silicon)** and **Windows x64 (Intel/AMD)**. Windows ARM64 is not included.

- **Multiple queries on one connection:** use DBX's native **+ / New Query** button. Each tab has its own SQL, partition key, parameters, page size and database/container location. A new tab inherits the source tab's last selected location and starts with default query input, without executing a query or copying results and document drafts.
- **Resume each workspace:** restored tabs load their own saved inputs and location. Ordinary sidebar reopen continues to reuse an existing tab. Explicit database/container changes update the shared connection default used by future initial workspaces and MCP, while other open tabs keep their own location.
- **Independent lifecycle:** closing a workspace flushes its pending input save and cancels only its own query/discovery. Other workspaces remain usable.
- **Windows x64:** native CI and release builds include the backend executable and bundled UI. End users do not need Node.js, Go or Python. Build and verification paths support spaces and non-ASCII characters.

## Upgrade and local data

The plugin identity, saved connections, Account Keys and read-only settings remain the same. No new host permissions or MCP tools are added; MCP remains read-only.

SQL and parameter text are stored locally as plaintext in the plugin's private data directory. Per-workspace input uses `query-input-workbench-v1`; locations use `workbenches-v1`. Legacy input is migrated when an ordinary workbench first reads it. New Query tabs do not overwrite the ordinary reopen fallback. Query results, unsaved document bodies and undo history remain memory-only. Windows access control relies on the host data directory ACLs; Unix private file modes are not evidence of Windows ACLs.

Older DBX versions retain their previous New Query behavior. Account Key authentication and existing cross-partition query pipeline limitations remain unchanged. Query history/favorites, pinned documents and document comparison are outside this release.

## Installation and validation

The published GitHub Release workflow builds **unsigned review candidates** for both targets. Marketplace availability follows store review, signing and merge; ordinary users should install the signed store packages.

Windows x64 CI has passed frontend, Go race/vet, complete Chromium browser tests, native packaging and execution of the packaged backend against a local mock service. **Native Windows DBX/WebView2 device testing is deferred**, so Chromium CI is not a claim of native WebView2 verification.

On macOS, native DBX validation confirms that + creates independent tabs, source location is inherited, new inputs start blank/default, switching tabs preserves independent inputs, and closing test tabs preserves the original workspace and its existing results. Restored locations/inputs, draft/result isolation and lifecycle behavior are also covered by automated tests using the production Go sidecar and local mock service. Validation does not modify business documents. See [validation records](https://github.com/fwrq41251/dbx-plugin-cosmosdb/blob/v0.26.0/docs/VALIDATION.md).
