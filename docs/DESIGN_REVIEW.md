# 代码设计检查（0.22.0）

本次使用 Open Code Review 委派模式解析文件和规则，由 Codex 结合源码执行检查；未调用外部模型。范围为工作区待提交代码，以及宿主适配、错误契约、测试目录和数据编辑模型。以下建议是已定位到代码的维护问题，不是未经验证的数据丢失或安全漏洞推断。

## 本轮已处理

- 多语言改为稳定消息键、独立中文/英文词典及语言注册表。去除“识别中文”和“缓存已渲染字符串再反查”的机制，改用显式 UI 标记与消息对象；连接表单的翻译由同一注册表生成。
- 修复节点脱离 DOM 后重新绑定却不再更新语言的问题；缓存中的未定义分区键标签随语言更新，实际字符串键不翻译。
- 文档差异增加 `kind: add/remove/replace`，Patch 使用操作类型，不再通过中文“（删除）”决定是否删除；预览文字与执行语义分开。
- 查询失败后的耗时保存为快照，后续切换语言不重新计算失败耗时。
- JSON 格式化避免反复对已生成输出 trim。相同本机 Node 样本中，12000 个模拟对象（457781 个字符）从约 1327 ms 降至约 8 ms；1000/4000/12000 项输出逐字相同。该数据是本机微基准，不代表 DBX、网络查询或 Cosmos RU 的端到端性能。

## 0.23.0 后续处理结果

用户确认后已按原建议实施以下三项；保留下面的初始发现，便于追踪改动原因。

- `query-session.mjs` 管理执行、分页快照和取消；`document-session.mjs` 管理文档身份、保存和删除；`scope-session.mjs` 管理元数据分页及成功后提交的范围切换。三个模块各有独立状态，`app.mjs` 负责 DOM 渲染和宿主协调，继续共用 `epoch` / `operation` 失效防护。没有引入框架，也没有将全部 DOM 搬到新文件。
- 后端校验显式携带稳定 `reason`，服务错误附加脱敏参数；RPC 编号、message、HTTP category / position 等保留。缓存和位置警告增加 detail，MCP 结果 JSON 增加 reason / args，工具权限和输出预算不变。前端通过 `service-reasons.json` 映射词典，未知原因保留原文；旧文本适配仅用于兼容。
- 每次浏览器测试生成独立的宿主数据、插件数据、SDK 根目录及端口，禁用复用旧服务。父运行器在 Playwright 和服务退出后校验所有权再清理；失败截图留在忽略提交的 `test-results/<run-id>`。构建输出使用原子替换，避免并发读取半份 UI。手动开发继续使用持久化 `.dbx-dev`。

## 初始建议

### 中：主工作台职责集中

定位：`src/app.mjs` 的全局 `state`、`action/invoke`、`query`、`renderPage`、`renderFields`、`saveDocument` 和范围选择逻辑。

同一个模块同时管理连接生命周期、RPC、分页、分区发现、文档草稿和 DOM。修改一处状态可能影响多个操作，例如查询取消、范围切换与写后刷新都依赖 `epoch`、`operation`、`busy`。这些防护已有回归，但状态边界分散会增加后续改动成本。

建议先提取查询会话和文档会话，再提取范围选择控制器。会话对象管理身份、快照及失效条件；渲染函数读取会话状态，控制器发起 RPC。按现有行为逐块提取，保留现有测试，不需要更换 UI 框架。

### 中：后端错误仍缺少完整的稳定原因标识

定位：`backend/main.go` 的 `rpcError`，`backend/service_errors.go`，`src/legacy-service-messages.json`。

服务错误部分已有 HTTP 状态、category 和 position，但很多本地校验仍使用通用 `-32602` 加消息文字，缓存/范围警告也返回文字。当前 UI 需要兼容旧中文消息契约；自动覆盖测试可以发现遗漏，但不能消除后端措辞与前端适配的耦合。

建议在现有错误 data 中补充稳定 `reason` 和参数，警告同样采用结构化标识。保留 message 和旧客户端兼容；UI 根据 reason 选择消息键，未知错误继续显示原文。需要单独设计和回归 RPC/MCP 兼容性，不在本轮顺带更改协议。

### 低：浏览器测试目录需要按运行隔离

定位：`playwright.config.mjs` 的固定 `.dbx-dev/e2e-plugin-scope`，`scripts/dbx-cli.mjs` 的固定 `.dbx-dev/plugin-data`，`tests/browser/support.mjs` 的同一偏好和范围目录。

单轮测试使用一个 worker，当前没有据此推断并发缺陷。但反复运行会积累测试连接及缓存；本轮失败快照中已有大量历史 E2E 连接，调试界面和错误快照明显膨胀。两轮测试也不能可靠隔离。

建议区分手工开发的持久化目录与 E2E 的临时目录：每轮生成独立根目录，同时传给宿主、插件和测试夹具，结束后清理。保留显式选择持久化目录的手工调试方式。
