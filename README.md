# DBX Cosmos DB NoSQL 插件

免费、MIT 开源的 DBX 独立插件。连接 Azure Cosmos DB **for NoSQL**，无需 VS Code 或商业 JDBC 驱动。

## 当前功能

- DBX 连接表单、Account Key 认证、真实连接测试、数据库与容器浏览。
- Cosmos SQL 查询、参数化查询、可选分区键、逐页读取、上一页缓存。
- CodeMirror 6 SQL / JSON 编辑器：高亮、行号、搜索与匹配数、撤销；JSON 折叠、精确格式化和语法错误行列定位。
- Cosmos SQL 关键字、常用函数、查询参数与已知字段路径补全。文档面板可调整宽度或展开。
- 分区键自动加载全部候选、关键词过滤、暂停与续读；显示加载进度与 RU。
- 保存到容器层的连接，重开时直接进入数据库和容器；兼容原有 Account 连接。
- 当前页 RU、耗时、Activity ID；表格 / JSON 视图；当前页 JSON 导出。
- 按 id + 分区键读取完整文档，新增、替换、删除文档。
- 默认只读；更新和删除使用 ETag，检测并发修改；写操作不自动重试。
- 表格、JSON 编辑和传输保留大整数与小数原文精度。
- 新增时继承当前分区键并生成 UUID；保存 / 删除前预览字段差异；写入后自动刷新上次查询与分区键缓存。
- 字段视图支持筛选、类型保持的编辑与字段增删；默认使用带版本条件的 Patch 局部更新。

## 在 DBX 中安装

`0.15.0` 开发候选版兼容目标为 DBX **0.6.58+**、Host API 1.x、sidecar protocol v1。当前商店版 `0.8.0` 支持 DBX 0.6.49+，不含下述 MCP 功能。

打开 **DBX → 插件中心 → Marketplace**，搜索 **Cosmos DB NoSQL**，确认发布者为 `fwrq41251`，点击安装。官方商店自动验证安装包签名，无需开启“允许安装未签名开发包”。

正式插件 ID 为 `io.github.fwrq41251.cosmosdb`，当前商店版为 `0.8.0`，支持 macOS ARM64（Apple Silicon）。其他平台暂未提供商店安装包。[上架记录](https://github.com/t8y2/dbx-store/pull/384)。更新或重装前先关闭使用此插件的连接；同一正式插件身份的连接可在安装后重新打开。

新建连接时选择 **Azure Cosmos DB for NoSQL**：

| 字段                | 内容                                                       |
| ------------------- | ---------------------------------------------------------- |
| Account Endpoint    | `https://your-account.documents.azure.com:443/`            |
| Account Key         | Azure Portal → Cosmos DB 账号 → Keys 中的主 / 次密钥       |
| 数据库 ID / 容器 ID | 一起填写作为默认打开位置；均留空则保持 Account 连接。      |
| 只读                | 默认开启；需要编辑时关闭。DBX 自身的只读连接设置仍会生效。 |

Key 由 DBX Secret Store 保存，只有连接生命周期的本地后端收到密钥。工作台不会收到密钥。插件不包含遥测、云中转或 AI 服务。

默认位置在测试连接时直接验证，打开后自动进入保存的数据库和容器，无需 Account 层的数据库列表请求。0.15.0 起，界面可以临时选择其他数据库/容器；保存的范围是默认打开位置，不再是界面访问边界。Account Key 在 Azure 中原有的权限及连接只读设置保持不变。MCP 仍限定在保存的数据库和容器内。

打开保存的连接，依次选择数据库、容器并运行 `SELECT * FROM c`。双击结果行仅预览，**读取完整文档** 后才允许编辑，避免用查询投影覆盖完整文档。

分区键以 JSON 数组填写，例如 `["tenant-a"]`、`[42]`、`[null]`；不存在的分区键值用 `[{}]`，层级分区键依次填写所有组件。
参数示例：`[{"name":"@id","value":"order-001"}]`。

## 结果表格与查询状态（0.15.0）

表格始终显示当前页查询返回的所有字段，不提供单独的列勾选或搜索。需要减少字段时使用 SQL 投影。id 固定在左侧；拖动列头右缘调整宽度，聚焦分隔条后也可用左右方向键调整。列宽按端点、连接、数据库和容器保存，只保存列名与尺寸。旧版隐藏列和固定开关不再生效，读取旧布局时自动清除这些设置并保留列宽。

单击只选择单元格，不切换文档或打断未保存草稿。选中格有明确描边，方向键移动，`⌘ / Ctrl + C` 复制；也可点击按钮复制单元格或整行 JSON，保留大整数及嵌套 JSON 精度。整行复制的是查询结果投影，并不代表完整文档。“筛选当前页”仅筛选已加载的这一页，不发送查询；筛选同步到表格、JSON 和当前页导出，导出保留所有字段。可一键清除；翻页保留筛选，新查询成功后清除。JSON 模式隐藏仅表格适用的工具。

查询结果的 JSON 视图也使用只读 CodeMirror，首次切换到 JSON 时才创建，表格模式不预先格式化结果。支持高亮、行号、行号旁的嵌套折叠，以及 `⌘ / Ctrl + F` 搜索、匹配数量和上下项定位；也可用现有工具栏内的搜索入口。“复制 JSON”复制当前显示的完整页，存在本页筛选时复制筛选结果，保留数字原文，不受折叠或屏幕虚拟滚动影响。搜索和折叠不额外访问数据库，也不影响导出。页面数据未变时，表格 / JSON 来回切换保留阅读位置和折叠；换页、修改筛选、重新查询或切换容器时更新内容并清除旧阅读状态。

在 JSON 结果项内右键，选择“复制此项 JSON”或“打开完整文档”；点在嵌套字段或折叠内容上也会定位整个顶层结果项。复制保留查询投影的数字原文，不受折叠影响。打开完整文档只使用该项自身的非空字符串 id 和完整分区字段；投影缺字段时禁用，不借用查询框中的分区键。此操作会点读数据库，并沿用未保存草稿确认。键盘可用 Shift + F10 / 菜单键打开，方向键选择、Enter 执行、Escape 关闭。根数组括号、项间空白或整体折叠不代表独立结果项，保留原生菜单。

每行的“打开文档”按本行 id 和完整分区键直接读取完整文档；投影缺少 id 或分区字段时改为“预览”并说明原因，不借用其他查询的分区键。双击结果行或在选中单元格按 Enter 可预览查询投影。未保存的文档草稿仍需确认后才能切换。

结果数量、RU 与耗时常驻标题，复制或预览不覆盖指标；条件已修改、取消或失败后保留旧结果时显示来源标记，悬停可查看原 SQL 和分区键。“收起 SQL”和“收起文档”可扩大结果区，打开文档时自动恢复文档面板。

查询执行期间显示耗时与“RU 未知”，可点击“取消查询”。取消通过独立请求传到 Go HTTP context；立即允许重新查询，并阻止旧响应覆盖新结果。取消保留上次成功结果，已产生的 RU 不会退回，未收到响应时不推断为 0 RU。查询成功、失败和取消分别显示对应状态；写入操作不提供此取消入口，避免误判写入结果。

## 工作台布局（0.15.0）

容器连接使用顶部“连接 / 数据库 / 容器”路径，隐藏固定侧栏；名称可悬停查看全文，宿主未提供连接名称时只显示数据库与容器。点击路径旁的“容器信息”可查看分区路径、元数据并显式刷新；打开面板只展示已有元数据，不额外访问 Azure。支持 Escape、外部点击与焦点离开关闭。Account 连接继续使用数据库、容器选择侧栏。

点击面包屑中的数据库或容器名称，可打开支持本地搜索和键盘选择的列表。列表按需读取所有分页，当前工作区内缓存，刷新列表可显式重新加载；Azure 不允许列举时保留当前范围，默认容器仍可使用。切换前确认未保存草稿；新数据库的容器列表读取成功后才提交切换，失败保留原范围和草稿。切换后清除旧结果和文档定位，按新容器隔离分区候选、已选键、字段提示及列宽；不自动执行 SQL。元数据刷新保留临时位置，重新打开连接恢复保存的默认位置，不修改连接或凭据。

![数据库与容器选择（本地模拟数据）](docs/scope-picker.png)

字段面板将普通值排成紧凑行，长文本和 JSON 使用多行区域；字段路径、类型与只读状态分层显示。删除图标在悬停或键盘聚焦时出现，触屏保持可见；只读字段不显示删除入口。草稿修改的字段带标记，底部显示变化数量，删除的字段也计入数量；改回原值后标记清除，无效输入会提示修正而不推断数量。既有精度、分区键保护、写入预览与 ETag 冲突规则保留。

深浅主题采用中性色背景，绿色用于主要操作、选中与焦点；次要操作使用轻量按钮，图标和焦点样式统一。

## 单文档增删改

写入连接需要可写 Account Key，并关闭连接表单中的“只读”，保存后重新连接。工作台会说明当前只读状态；Azure 只读 Key 本身无法通过关闭插件开关变成可写 Key。

- **新增**：先选择查询分区键，再点击新建，草稿自动生成 UUID 并填入分区字段。可以编辑 id 或点击“生成 UUID”，也可通过文档分区键选择器同步更新草稿中的分区字段。使用 create，不覆盖已有相同 id + 分区键的文档。
- **修改**：读取完整文档后默认进入字段视图，可按字段路径筛选，直接修改字符串、数字和布尔值；数组、null 和空对象使用字段内的 JSON 输入。支持添加与删除字段，也可以切换 JSON 编辑整个草稿。id 和分区键锁定，系统字段不放入可编辑正文。保存前显示原值、新值与增删情况；没有变化时不提交。
- **删除**：先读取完整文档，确认目标与被删除字段后执行；使用读取时的 ETag，若已有并发修改会返回冲突。

正文分区键会在前端和后端校验。写入成功后自动按上次成功查询刷新到第一页；刷新失败会明确说明文档已写入成功，清除旧结果并保留已保存文档，不自动重试写入。新分区键直接补充持久缓存，删除时仅检查目标分区还有没有文档，只有最后一条消失才移除对应候选，无需全容器重新发现。

## 字段编辑与局部更新

已有文档默认使用局部更新：仅将变化转换成 `set` / `remove` Patch 操作，未修改字段不随请求发送。嵌套对象按 JSON Pointer 字段路径更新；数组作为一个整体值，避免数组索引移动导致误修改。输入无效数字或 JSON 时禁用保存，切换视图不会悄悄丢弃错误输入；修正后可继续操作。

Patch 每次最多 10 个操作，超过时会停止并提示；需要时在“保存方式”中明确选择“完整替换文档”。不会自动拆成多次 Patch，也不会自动降级为完整替换。版本检查同时使用 `If-Match` 和基于原 `_etag` 的服务端条件，发生并发变化返回 412，保留本地草稿，不重试写入。

前后端都禁止 Patch 修改 id、分区键及其父子路径、系统字段。局部更新减少提交内容，不保证 RU 一定低于完整替换。

![字段编辑（本地模拟数据）](docs/field-editor.png)

SQL 与 JSON 使用本地打包的 CodeMirror 6，不访问 CDN。SQL 输入时自动显示候选，也可按 `Ctrl + Space` 手动唤起，无需额外按钮。参数候选来自查询参数输入；字段候选只从已读取的完整文档和简单 `SELECT [TOP n] * FROM alias` 根文档查询中学习，按连接、数据库、容器隔离，仅在当前工作区内存中保留，不额外扫描容器。支持根别名、嵌套点路径、简单 `JOIN item IN c.items` 别名；特殊字段名插入方括号访问。候选不代表完整容器结构，复杂子查询与别名作用域暂不提供完整语义分析。

JSON 格式错误会显示行列，点击提示可定位；无效草稿不可保存或切换至字段视图。格式化仅调整空白，保留长整数及小数原文，并支持撤销。读取另一份文档会重置编辑器撤销历史；切换字段 / JSON 视图保留草稿。`⌘ / Ctrl + Enter` 仅在查询区运行查询，避免打断 JSON 草稿。`⌘ / Ctrl + F` 搜索当前编辑器；匹配数量最多统计 10000 项，超出显示 `10000+`。拖动文档区左侧分隔条可调整宽度，聚焦分隔条后左右方向键也可调整；“放大 / 还原”按钮切换文档面板大小。JSON 工具收在“更多”菜单：格式化、折叠嵌套和展开所有层级；折叠嵌套保留根对象和顶层字段，没有嵌套内容时显示不可用原因。完整文档读出后自动收起定位表单，并在同一工作区记住所选的字段 / JSON 视图。

SQL 编辑器有选区时，运行按钮显示“运行选中 SQL”，按钮与 `⌘ / Ctrl + Enter` 均只发送选区的原文；没有选区时执行全文。空白选区和多个选区会提示并停止，不回退执行全文，也不自动拆分多条语句。查询仍使用当前容器、参数和分区键。结果标题标明选区的原始行范围；翻页和写入后的刷新沿用上次成功查询快照，不读取后来改变的选区。查询正文只保留在工作区内存，不新增历史持久化。

服务返回可信 SQL 语法位置时，编辑器会标记对应字符并滚动到附近，提示整个编辑器中的行列；点击提示可将光标定位到错误处。选区内位置会换算回完整编辑器；修改 SQL、切换容器或重新执行会清除旧标记。来源 SQL 已改变、位置缺失或越界、其他类型服务错误只保留文字反馈，不猜测错误位置。旧宿主如丢失结构化错误数据，可识别插件自身已脱敏的位置提示；不展示服务端原始错误正文。

SQL 语法错误、分区键不匹配、跨分区管线限制、索引不足、只读凭据、防火墙和并发冲突会显示对应中文说明；服务有提供 SQL 位置时会提示字符位置。不直接展示服务端原始错误中的 SQL 字面值或文档内容。无法分类的错误保留 HTTP 状态和通用说明。

## 分区键选择

查询和文档区域的分区键输入框旁均有 **选择** 按钮。打开后输入关键词，即可过滤已知候选；点击候选填入对应输入框，再运行查询或读取文档。字符串、数字、null 和大整数会保留原始类型与精度，也可以继续手动填写 JSON 数组。

打开选择器先读取本地持久缓存，已有完整缓存时不发起分区键发现查询。首次没有缓存时自动加载，候选一到即可筛选和选择；关键词过滤在本地进行。查询结果中包含完整分区字段时，也会补充当前工作台的候选。

0.4.0 使用索引跳读代替 DISTINCT：在每个物理分区内，通过 `TOP 1`、`ORDER BY` 和严格大于上个值的条件跳过重复记录。字符串和数字分别枚举，再检查布尔值、null 和未定义值。每次 RPC 最多执行一次数据查询；后续请求复用分区元数据。当前支持单路径分区键，层级分区键或缺少所需索引时显示错误，保留手动输入，不自动退回文档扫描。

发现的候选、完成状态和续读游标按 Account Endpoint、连接 ID、数据库和容器隔离，保存到操作系统的用户缓存目录 `dbx-plugin-cosmosdb/partition-keys-v1/`。文件仅当前系统用户可读写，不保存密钥或文档正文。重开工作台或重连后可复用；界面标明缓存时间和本次 RU。缓存是历史快照，不会因时间自动全量刷新；新增或删除分区键后点击 **刷新列表** 重新发现。上次查询所选分区键仍只保留在工作台内存中。

关闭选择器或暂停会停止后续请求，重新打开可继续；已发送的一次请求仍可能返回。429 会等待后重试。每轮自动加载达到 2000 RU 后暂停，保留候选和进度；需要时可继续。缓存不可用时显示提示。加载尚未完成时，关键词仅匹配已知候选；并发数据变化、容器重建或物理分区拆分可能需要刷新。

## 开发与验证

需要 Node.js 22+、Go 1.22+。最终用户安装 `.dbxp` 后无需这些运行时。

普通用户从商店安装即可。从源码构建的安装包生成在 `dist/`；源码仓库 Release 提供的是未签名审核候选包，仅用于开发验证。手动安装开发包时，在 DBX → 插件中心 → 设置 → 第三方与开发者选项启用“允许安装未签名开发包”，再选择 `.dbxp` 安装。正式发布流程见 [发布与商店审核](docs/RELEASING.md)。

```bash
npm ci
npm run build
npm test
cd backend
go test -race ./...
go vet ./...
cd ..
npm run test:browser
npm run package
```

`npm run dev` 启动官方 DBX 浏览器开发宿主。`.dbx-dev/` 是独立的本地开发配置，不读取 DBX 用户数据库；其中的凭据是开发宿主保存的明文，请仅使用测试账号。

浏览器测试通过本地模拟 Cosmos HTTP 服务、真实 Go sidecar 和 DBX 官方开发宿主验证连接、查询、分页、只读、精度、ETag 冲突和文档增删改。测试用默认端口 5191、18081。Mac 默认使用已安装的 Chrome；CI 安装 Playwright Chromium。

可选真实 Azure 验证：`python3 scripts/validate-live-cud.py --resource-group <group> --account <account> --database <database> --package <native.dbxp> --run`。脚本仅在本次新建的临时容器操作假数据，结束后删除容器并确认不存在；可写 Key 仅放在内存，不写入 DBX。Serverless 使用按请求计费；预配账号会临时分配 400 RU/s，请仅在开发账号显式运行。

## MCP 只读工具（0.9.0 起）

通过官方 DBX MCP Server 接入，不需要单独启动 Cosmos 插件服务器，也不需要把 Account Key 配置到 AI 客户端。当前已验证的稳定组合为 **DBX 0.6.58 + `@dbx-app/mcp-server@0.4.132`**。插件 Manifest 使用该版本支持的 `external_tools` 和 MCP 只读标注。`0.4.134` 已要求新的逐工具权限声明及插件授权，与 0.6.58 的界面和 Manifest 契约不配套；此候选版暂不支持该组合，不能仅升级独立 MCP Server。后续适配需要同时升级宿主及 Manifest。

在 DBX 设置 → MCP → 权限管理中允许目标连接，并在工具列表添加以下四个精确工具名称。客户端只开放它们以及 `dbx_list_connections`；避免用通配符自动开放未来新增工具。

| 工具 | 用途 | 主要参数 |
| --- | --- | --- |
| `dbx_cosmosdb__container_info` | 读取保存容器的元数据与分区路径 | `dbx_connection`、可选 `refresh` |
| `dbx_cosmosdb__query` | 指定逻辑分区读取一页结果 | `sql`、`partition_key_text`、可选 `parameters_text`、`page_size`、`cursor` |
| `dbx_cosmosdb__read_document` | 按 id 和完整分区键点读 | `id`、`partition_key_text` |
| `dbx_cosmosdb__cached_partition_keys` | 本地历史分区缓存过滤与分页 | 可选 `filter`、`offset`、`limit` |

所有工具通过 `dbx_connection` 选择已保存并放行的容器连接，不能覆盖数据库、容器、Endpoint 或密钥。Account 层连接需先保存数据库和容器。MCP 只读分发器与界面写入分开，即使保存连接可写，也不提供 MCP 增删改。内置 DBX AI 工具保持关闭，仅开放外部 MCP。

分区键和查询参数使用 **JSON 文本字符串**，防止宿主解析 JSON 数字时损失精度。例如查询工具参数：

```json
{
  "dbx_connection": "my-test",
  "sql": "SELECT c.id FROM c WHERE c.amount = @amount",
  "partition_key_text": "[\"tenant-a\"]",
  "parameters_text": "[{\"name\":\"@amount\",\"value\":9007199254740993}]",
  "page_size": 20
}
```

查询返回 `documents_json`（保留数字原文）、`count`、`ru`、`metadata_ru`、`duration_ms`、`activity_id`、`has_more` 和可选的 `next_cursor`；点读和元数据返回 `document_json`。下一页保留原参数，将 `next_cursor` 填入 `cursor`。每页默认 20、最多 100 条，不自动翻页、重试或发现分区键。查询和点读使用容器元数据校验完整分区键。元数据按端点、连接、凭据身份、数据库和容器在 sidecar 内存缓存五分钟；缓存命中不请求 Azure。`metadata_source` 标明 `cache` / `live`，并返回 `metadata_cached_at`、`metadata_expires_at`。`ru` 包含实际发生的元数据读取成本，`metadata_ru` 单独列出；缓存命中为 0。容器相关的 400 / 404 会使该缓存失效，下次调用重新获取，不自动重试失败查询。显式调用 `container_info` 并传入 `refresh: true` 可立即刷新。空页可能仍有下一页。游标绑定连接、凭据身份、SQL、参数、分区键及每页大小，10 分钟或 sidecar 重启后失效；仅内存保存，最多 256 个游标。

输出正文预算为 192 KiB，超出会明确失败并保留已知 RU，不静默截断文档或返回跳过结果的游标；查询时可减少每页数量或使用字段投影。AI 客户端仍可能施加自己的输出长度限制。分区缓存工具不发 Azure 请求，返回是否找到缓存、是否完整和缓存时间，不把已知候选当成实时完整列表。

Codex 配置示例（路径改为实际安装位置；连接 ID 使用本机保存连接的 ID）：

```toml
[mcp_servers.dbx]
command = "/absolute/path/to/dbx-mcp"
enabled_tools = ["dbx_list_connections", "dbx_cosmosdb__container_info", "dbx_cosmosdb__query", "dbx_cosmosdb__read_document", "dbx_cosmosdb__cached_partition_keys"]
startup_timeout_sec = 30
tool_timeout_sec = 60
default_tools_approval_mode = "writes"

[mcp_servers.dbx.env]
DBX_MCP_PLUGIN_TOOLS = "flat"
DBX_MCP_SCOPE_CONNECTION_IDS = "your-saved-connection-id"
```

可选端到端验证：`python3 scripts/verify-mcp.py --binary /absolute/path/to/dbx-mcp --connection my-test --partition-key-text '["tenant-a"]'`。脚本通过真实 MCP 的初始化、发现和调用验证元数据、缓存、查询、点读及可用的下一页；仅输出验证结果，不打印凭据或文档内容，不写业务文档。macOS 如提示 `KEYRING_ACCESS_FAILED`，按官方说明对同一个 MCP 可执行文件运行一次 `--authorize-keychain`，不要将此参数放入客户端配置。

## 首版边界

- 已在本机 DBX 0.6.49 安装，并以真实 dev 账号的只读 Key 验证查询及点读。0.5.0 已在单独创建并清理的 Azure 临时容器验证真实单文档增删改、409 / 412 冲突与只读拦截。
- 当前使用 REST gateway，不实现 Azure SDK 的跨物理分区查询计划 / 合并管线。需要该管线的查询形态可能失败，可指定分区键；不宣称完整 SDK 查询兼容。
- Account Key 认证；暂不支持 Entra ID、SSH / DBX 代理路由、自动区域切换或吞吐量 / 索引修改。
- 分区键加载会处理 429 等待重试；查询及文档操作不自动重试。请求超时后应先重新读取，确认写入是否已完成。
- 查询按页读取；导出仅当前页且上限 1 MiB。单服务响应上限 6 MiB；过大时减小每页数量。
- 写入后仅刷新上次成功查询的第一页；如失败会清空旧结果并提示手动重跑。批量修改 / 删除仍未实现。
- 宿主关闭标签页或重载插件会丢失内存中的草稿；插件内切换容器、查询或文档会提示未保存修改。
